# P0 Browser Request Boundary ExecPlan

## Current behavior

The FastAPI service trusts loopback reachability and CORS. A malicious website can
send a simple cross-origin request directly to `127.0.0.1:8001`; CORS prevents the
page from reading the response but does not prevent state changes. Next.js performs
Host, Origin, and pairing-session checks only when a request passes through port
3000, so direct backend requests bypass that boundary.

## Harm being prevented

An untrusted browser page must not activate or test a Provider, start or mutate a
Run, alter high-risk approvals, install an update, or invoke any future API route on
the operator's computer.

## Target behavior

1. Every `/api/*` route except `/api/health` requires a per-start, high-entropy
   internal token checked with constant-time comparison.
2. The token is generated by each desktop launcher, stored with user-only
   permissions, and passed only to the loopback backend and Next.js server.
3. Next.js injects the token into proxied API requests. Browser JavaScript never
   receives it.
4. Null, public/foreign, and cross-site browser origins are rejected even if a
   valid internal token is present. Loopback and private-LAN frontend origins remain
   compatible with paired phones.
5. Unknown backend Host values remain rejected before application code runs.
6. Missing configuration fails closed for API access while health checks remain
   available for launcher supervision.

## Compatibility requirements

- Preserve all API paths, request and response schemas, Run lifecycle, mobile
  pairing, SSE replay, diagnostics, and updater behavior.
- Keep FastAPI bound to loopback.
- Do not persist the internal token in SQLite, browser storage, URLs, diagnostics,
  or logs.
- Existing source and packaged launchers on macOS and Windows must share one token
  across backend and frontend restarts.

## Verification

- Backend adversarial tests for missing/wrong token, evil/null/missing Origin,
  simple form/text requests, cross-site fetch metadata, and rebinding-style Host.
- Positive tests for loopback and private-LAN origins through the internal token.
- Frontend unit test for token injection and fail-closed behavior.
- Existing backend coverage suite, frontend type/unit/build, Chromium E2E, launcher
  syntax checks, release consistency, and dependency audit.

## Rollback

Revert the feature commit. Launcher token files are disposable startup material and
are deleted by the stop scripts; no database migration or user-data rollback is
required.

## Outcome

- FastAPI now protects every application API except health with a constant-time
  internal-token check plus Host, Origin, port, and Fetch Metadata validation.
- Next.js removes browser-supplied auth headers, injects the server token, and
  fails closed when the launcher configuration is missing.
- Source and packaged launchers on macOS and Windows share one user-private token,
  verify a non-secret process identifier, and replace stale mismatched processes.
- Backend: 193 tests passed, 79.34% total coverage, 100% coverage for the new
  request-boundary module.
- Frontend: TypeScript, 10 unit tests, and the production build passed.
- Chromium E2E: 35 tests passed on isolated ports, including mobile, updater,
  diagnostics, Provider configuration, Run lifecycle, and finalization flows.
