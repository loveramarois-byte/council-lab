# Decisions

## FastAPI + Next.js

保留定制的一屏四席界面和本地 API。成熟框架只接管后端编排，不用通用 Studio 替换产品交互。

## LangGraph 持久工作流

动态讨论席顺序、最终确认点、总结、失败节点和恢复位置由 LangGraph 状态图表达。选择它是为了获得确定性路由、SQLite checkpoint、受条件约束的进程重启恢复和可测试的节点边界，而不是引入自由群聊。

## 完整日志与工作上下文分离

公开发言永久保存在 Run 中。模型只接收按 Token 预算生成的工作窗口：原问题、确定性选择的早期锚点、最近发言和最新用户插话。裁剪只影响下一次请求，不修改证据记录，也不会产生隐藏的摘要模型调用。

## Checkpoint 独立数据库

业务 Run 和 LangGraph checkpoint 使用两个 SQLite 文件。SQLite 同时只有一个写入器的限制使分库比增加重试或延长锁等待更可靠。删除 Run 时同步删除该 `thread_id` 的 checkpoint。

## CC Switch Local Router 一等 Provider

CC Switch 是本地上游路由，不是第二套供应商管理器。Council 做连接探测、协议选择、模型映射和错误展示；当公开模型目录为空时，只读本机 CC Switch 数据库中的近期成功 Codex 请求模型名，不读取 Provider 配置、上游地址或密钥，也不修改数据库。供应商切换与故障转移仍由 CC Switch 完成。

## 每席配置在创建时固化

四个讨论席与总结席可独立选择 Provider/model。Run 保存完整公共配置快照，是为了让历史记录可解释、重启恢复可重复，并避免全局 Provider 设置变化篡改旧运行。密钥仍只保存引用，不进入快照。

## 最终总结必须由用户确认

默认在最后一个讨论席后进入 `awaiting_final_input`。额外一次点击换来明确的人类控制点，并保证最终补充进入总结请求；需要无人值守的调用方可显式启用 `auto_summarize`。自动总结路径不会先持久化或广播等待确认状态，避免轮询客户端与手工总结产生竞态；高风险模式在代码层禁止自动总结。

## 短任务保守精简席位

快速档的短定义和确定性算术使用第一讨论席与总结席，共两次模型调用。决策、风险、预测、模糊数量和高风险领域始终保留完整四席。Run 只保存实际参与席位，但五席配置本身不被修改，历史 Run 继续按各自快照读取。

## 不伪造成本、核验和置信度

没有可靠的统一价格表时只执行模型调用数、Token 和完整运行时间边界。没有外部工具证据时不宣称事实已核验，也不显示没有计算依据的百分比置信度。

## 不展示思维链

持久化只包含公开答案、依据、反例、上下文裁剪快照和不确定性。隐藏推理不是产品输出，也不写日志。

## 本地可观测性

UI 显示工作流引擎、持久检查点数量和当前上下文 Token 使用量。默认不把非 OpenAI Provider 的追踪发送到第三方。

## 冻结资料全文，调用时再裁剪

Run 保存所选资料的完整提取正文、来源元数据和 SHA-256。这样资料后来被编辑或删除时，历史审议和导出报告仍可复核；模型请求只接收按上下文预算裁剪的工作副本，避免把持久化完整性与单次上下文容量混为一谈。

## 结果回访属于 Run，不属于模型结论

最终选择、预期结果、复盘日期、实际结果和席位观点验证状态由用户填写，写入原 Run 且不触发模型。它用于把“当时为什么这样判断”和“后来结果如何”连接起来，不把事后信息伪装成原始讨论的一部分。

## DecisionBrief 是独立的不可变结果快照

自然语言最终综合继续保存在 Run 中；`DecisionBrief v1` 另存于按 Run 和版本唯一的追加式表。这样新结果结构不会回写已完成 Run、Turn、高风险审批或审计记录。v1 从已经持久化的综合字段与公开表态确定性生成，不增加模型调用，也不解析 Markdown。简报保存成功后 Run 才进入 `completed`；保存失败会保留综合并允许直接重试。历史 Run 不自动回填，以免把新算法生成的内容伪装成当时产物。

席位支持度只表示公开讨论中的可观察立场，不是事实正确概率。没有外部核验时必须保留限制说明；阻塞矛盾不能与无条件推进并存，明确反对必须出现在少数意见中。未来的重新生成只能追加新版本，高风险审批绑定关系必须另行设计和复核，不能在 v1 中隐式改变。

## 输出契约扩展结果，不扩张角色和权限

一般决策、产品评审和技术架构评审共享固定四席、总结席、调用预算、checkpoint、SSE、幂等与高风险控制。契约只增加输入检查、公开 Prompt 指导和 `DecisionBrief schema v2` 的强类型扩展；旧 Run 和 v1 简报默认归入一般决策，不做回填。

扩展字段从已保存的问题、最终综合和结构化简报确定性投影，不增加模型调用，也不把字段存在解释为真实用户研究、代码运行、性能测试或外部核验。产品实验阈值和架构观测要求中的通用文字是待执行检查项，不是已经完成的证据。评测结果保存契约 ID，并可按契约分组执行指标，质量结论仍受全真实 Provider 与完整盲评门禁约束。

## 情景变化创建新 Run，不改写历史

预算、期限、事实或模型配置变化时，Council 创建带父子关系的新 Run。分叉点之前的公开发言可以复用，但必须在新快照和关系记录中标记来源；新 Run 的 Token、调用次数、简报、回访和高风险控制单独计算。复用 checkpoint 必须真实存在，模式或席位布局不兼容时拒绝复用。

高风险分叉不撤销也不继承父 Run 的审批。父审批继续作为历史审计证据，子 Run 创建全新的控制记录并从关键事实门禁开始；如果子 Run 与关系记录不能原子落库，控制记录进入失败关闭状态，模型任务不会启动。

## 评测结论需要全真实 Provider 与完整盲评

执行指标与质量评分分离。只要参与比较的任一 Provider 是 Mock，或并非全部案例和匿名答案都完成有效评分，输出就把 `quality_claims_allowed` 设为 false。引用支持率和未经支持主张由盲评者计数；成本只有在用户提供对应 Provider/model 的 Token 单价时才估算。

## 自包含运行时优先服务普通用户

macOS 和 Windows Release 内置后端、网页和 Node runtime，普通用户无需安装 Python/Node。当前社区构建只做 macOS ad-hoc 签名且未 notarize，Windows 没有商业签名；下载页和安装文档必须长期明确该边界，不能把“能启动”描述成“已通过平台认证”。

## 更新由已验证包和独立助手完成

运行中的后端只负责从固定官方 Release 下载、限制并校验包，不直接覆盖自身。通过 SHA-256 和 ZIP 安全检查后，由新版包内的独立平台助手停止服务、备份、替换和重启；失败时优先恢复旧版。这样更新失败不会把用户数据和 API Key 卷入应用目录替换，也避免运行中进程改写自身文件。源码模式只提示版本，不自动覆盖 Git 工作区。
