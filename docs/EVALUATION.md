# Evaluation

评测入口保留在 `/evaluations`，当前 UI 明确标注“仅使用本地 Mock 数据”。新增评测问题时，应给出问题类型、参考答案或可执行测试、来源和风险等级；比较快速、标准、严谨模式时记录事实准确率、引用准确率、验证覆盖率、未经证实主张数量、延迟、Token、成本和代理失败率。

没有真实 API 凭据时只运行 Mock 流程和 Provider 集成测试，不能把 Mock 结果写成真实模型表现。工作流回归还必须验证四席顺序、第五次总结、用户插话传播、上下文预算、SQLite checkpoint 数量、进程内存丢失后的当前节点恢复，以及删除 Run 时的 checkpoint 清理。后续接入搜索和代码沙箱后，VerificationResult 应保存工具、来源时间、限制和可复现命令。
