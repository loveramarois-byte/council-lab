# 传统文化联合研判模式

## 定位

该模式把“可重复的本地排盘”和“不可当作科学事实的传统解释”分开。它适合个人研究传统历法、八字与紫微体系的规则、差异和叙事边界，不是预测准确率产品，也不是高风险决策工具。

## 计算与四席

- `lunar-javascript@1.7.7` 计算公农历、四柱、柱五行和天干十神。
- `iztro@2.5.8` 计算紫微基础盘与十二宫。
- 联网时后端并发读取 Cloudflare、Google 与百度的 HTTPS `Date` 响应，至少两源在 5 秒内一致才标记为“联网已同步”；否则明确回退本机时钟。
- 校历席核对输入、时间与计算口径。
- 辨典席区分明确体系、规则来源和个人推断。
- 参派席比较八字、紫微及不同流派可能的一致和冲突。
- 证伪席寻找巴纳姆效应、确认偏误、事后归因与不可证伪表达。

`bazi-skill` 提供了有价值的解释与交互组织参考，但不是本模式中的计算引擎。`ziwei-doushu` 依赖 `iztro` 与 `lunar-javascript`，共享底层结果不能算独立交叉验证。本项目不打包其大型数据集，也不调用第三方命理服务。

## 固定解释体系

每个新 Run 会把用户选择的体系写入冻结快照、模型上下文和导出文件，避免同一份排盘在不同发言间混用规则。当前提供：

- 比较研读：八字与紫微分别解释，再标出一致、冲突和不能比较之处。
- 八字规则优先：四柱、五行和十神为主，紫微仅作为明确标注的对照。
- 紫微规则优先：命身宫、十二宫和星曜字段为主，四柱仅作为明确标注的对照。

每套体系均有固定的解释顺序、适用范围和限制；模型不得重新排盘、补写快照外字段或把一个体系的判断偷换成另一个体系的事实。体系提高的是过程一致性，不代表预测准确率或科学有效性。

六爻、暗动、月破等能力当前没有确定性起卦与排盘模块，因此没有开放为可用功能；只把《卜筮正宗》保留为资料索引，避免模型在没有卦象输入时猜盘。

## 输入口径

- 只接受 1900-01-01 至今天的公历日期。
- 记录出生时间及“准确 / 约数”精度。
- 性别只作为现有排盘引擎参数。
- 出生地可选。本机 Next 服务使用固定版本的离线城市坐标表解析城市级经纬度；只接受完整城市名或结构化的省/自治区 + 城市写法，不从任意句子片段猜测地点。原始自由文本不发送给模型或写入 Markdown/HTML 导出，只传递规范化城市名和本地计算结果；不收集姓名。
- 固定使用 `Asia/Shanghai` 民用时。
- 识别到城市后可按城市级经度与均时差校正真太阳时；结果同时保留民用时、真太阳时和校正分钟。
- 快照列出出生日柱、出生时辰及范围、出生时柱，咨询时刻的流年/流月/流日/流时，以及前后节气交接时刻。
- HTTPS 多源时间只提供秒级联网校时，不是专用 NTP 或天文台授时；联网结果由当前后端实例签名，新建 Run 会校验证明与 10 分钟新鲜度，但这只证明时间来自本次服务端多源采样，不证明传统解释正确。城市级坐标也不等于出生地点的精确经度。当前不处理历史夏令时。
- 服务端时间证明单独验签且不进入排盘快照 SHA-256，因此相同排盘输入的摘要不会随后端重启或签名密钥轮换改变；时间字段本身仍由快照摘要约束。

临界日期、时辰交界、节气交接和真太阳时敏感案例可能因引擎口径、城市级坐标或历史时制不同产生另一张盘。结果页和导出会明确记录时间来源、本次口径、引擎版本和快照 SHA-256。

## 隐私

出生资料属于敏感个人资料。浏览器只把原始排盘资料发给同源的本机 Next 服务，由服务端重新运行固定版本引擎、绑定联网时间证明并签发整份快照证明，不调用第三方命理 API；浏览器不能自行提交可信派生字段。只有用户在新建页明确勾选同意后，排盘字段与必要出生参数才会作为本次 Run 的冻结上下文发送给已配置的四个讨论席与总结席；原始出生地自由文本只保存在本机数据库的冻结快照中，不发送给席位，也不写入 Markdown/HTML 导出。席位和导出只使用规范化城市级地点和计算结果，两个内部证明也不会进入模型、界面或导出。数据继续遵守 Council 的本地数据库与 Provider 边界。

## 强制边界

- 固定使用“先独立初答”与专用模板。
- 禁止启用高风险控制或自动总结。
- 禁止注入历史决策记忆或选择专业决策输出契约。
- 医疗、用药、法律、投资、合规和生产操作意图在 API 与 Orchestrator 两层拒绝。
- 动作型表达同样拒绝，包括开药/停药、起诉/签约、交易与仓位、报税/监管放行、生产上线/回滚及相应英文表达；非行动性的历史和文化研究仍可使用。
- 传统解释不会进入 `verified_claims`、DecisionBrief、决策回访或长期记忆候选。
- 最终答案必须区分计算快照、传统解释、流派分歧、反证与限制、非约束性观察。

代码和测试通过只能证明软件按上述规则运行，不能证明命理解释或预测具有科学有效性。
