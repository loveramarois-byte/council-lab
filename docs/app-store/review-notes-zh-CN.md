# App Review 备注（简体中文）

## 审核路径

Council 不要求账号登录。首次启动后可直接使用内置 `Mock / council-mock` Provider 完成审核，不需要 API 密钥，不产生付费模型调用，也不会把问题发送给第三方模型。

建议审核步骤：

1. 保持默认 Mock Provider，新建一条普通审议。
2. 输入任意测试问题并进入圆桌，查看四席讨论、核验与最终汇总。
3. 在“历史记录”打开刚才的审议，检查结果和决策摘要。
4. 在“设置 → 软件更新”确认更新由 Mac App Store 管理。
5. 在“设置 → 手机连接”确认 App Store 版本只允许本机访问。

如需验证专业领域控制，可用“我应该根据网上信息自行调整处方药剂量吗？”创建医疗类审议。应用会要求关键事实、标示证据与专业复核状态，并保持未验证资质和非专业意见披露。此流程不会给出可直接执行的诊断或处方。

## 技术说明

- App Store 构建启用 App Sandbox。
- 内嵌前端和后端仅监听 `127.0.0.1`，用于原生窗口内的本机界面与数据处理。
- App Store 构建不开放局域网或手机访问，不包含直接发行版的更新脚本，也不会联系 GitHub 检查应用更新。
- 审议记录默认保存在应用沙盒容器内。
- 文件只在用户通过系统文件选择器明确选择后读取。
- 第三方 AI Provider 完全可选；只有用户自行配置并选择后，相关提示词和上下文才会发送给该 Provider。
- Provider 凭据通过 macOS 安全存储保存，不会写入诊断导出。

## 内容与安全边界

Council 是决策支持工具，不提供医疗诊断或处方、法律意见、投资建议或其他需要执照的专业服务。专业身份字段由用户自行填写，Council 不验证或认证资质。应用没有使用或暗示 Apple 对 Council、其输出或专业能力的认可。

## 审核联系

提交前填写可及时回复的审核联系人姓名、电话和邮箱。如审核环境出现启动问题，请附上 Review 设备和 macOS 版本；应用内“设置 → 诊断”可生成不包含 API 密钥的本机诊断资料。
